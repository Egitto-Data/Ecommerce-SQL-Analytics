# E-commerce Sales & Customer Analytics | SQL Server

## Project Overview

This project analyzes e-commerce sales performance and customer purchasing behavior using Microsoft SQL Server and T-SQL.

The objective is to transform transactional data into meaningful business metrics and insights that can support data-driven decision-making.

 **Data Disclaimer:** 

This project uses a **synthetic (dummy) e-commerce dataset** created for educational and portfolio purposes.

The dataset does not represent real customers, transactions, or business performance.

The project includes four CSV files:

- `customers.csv` — Customer information.
- `products.csv` — Product details and unit costs.
- `orders.csv` — Order dates and customer references.
- `order_items.csv` — Products, quantities, and selling prices for each order.

The data is designed to support SQL analysis of sales performance, customer behavior, repeat purchases, customer segmentation, product performance, and market basket analysis..

## Business Objectives

- Measure overall sales performance.
- Analyze monthly revenue trends and growth.
- Identify high-value customers.
- Calculate repeat purchase rate.
- Segment purchasing customers using RFM analysis.
- Evaluate product performance and estimated gross profit.
- Discover products frequently purchased together.
- Examine customers' historical purchasing activity.
- Identify registered customers who have never purchased.

## Database Schema

The project uses four relational tables.

| Table | Description |
|---|---|
| `customers` | Customer information, country, and signup date |
| `products` | Product names, categories, and unit costs |
| `orders` | Order records, customers, and order dates |
| `order_items` | Products, quantities, and selling prices per order |

### Relationships

- One customer can place multiple orders.
- One order can contain multiple products.
- One product can appear in multiple orders.
- `order_items` connects orders and products.

## Key Performance Indicators

### Sales Metrics

- **Revenue:** Total sales value calculated as quantity multiplied by unit price.
- **Orders:** Number of distinct orders.
- **Units Sold:** Total quantity sold.
- **Average Order Value (AOV):** Revenue divided by distinct orders.
- **Average Selling Price (ASP):** Revenue divided by units sold.
- **Units per Transaction (UPT):** Units sold divided by distinct orders.

### Customer Metrics

- **Repeat Purchase Rate:** Purchasing customers with at least two orders divided by all purchasing customers.
- **Recency:** Number of days since a customer's latest order.
- **Frequency:** Number of distinct orders per customer.
- **Monetary Value:** Total revenue generated by a customer.

### Market Basket Metrics

- **Support:** Percentage of all orders containing both products.
- **Confidence:** Percentage of orders containing Product A that also contain Product B.
- **Lift:** Measures how frequently two products occur together relative to their independent purchase frequencies.

A lift greater than 1 indicates a positive association in the observed data. It does not establish causation.

## How to Run the Project

1. Install or connect to Microsoft SQL Server.
2. Create a dedicated practice database.
3. Execute `00_create_schema.sql`.
4. Import the four CSV datasets into the matching tables.
5. Execute the analysis scripts.
6. Validate results using the data-quality checks.
7. Document findings supported by the actual query outputs.

`DATETRUNC` requires SQL Server 2022 or later.

## Limitations

- The validity of the findings depends on data quality and completeness.
- `LAG` compares rows, so missing months can affect MoM and YoY calculations.
- RFM scores depend on the selected scoring method and customer population.
- Historical activity span is not predictive Customer Lifetime Value (CLV).
- Market Basket Analysis identifies associations, not causal relationships.
- Estimated gross profit excludes expenses not represented in the dataset.
